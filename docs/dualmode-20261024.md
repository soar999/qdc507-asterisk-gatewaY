# Dual-mode integration source — 2026-10-24

## Publication status (read before using)

This is a **public source/test integration kit, not a complete, independently
rebuildable dual-mode deployment**. It preserves the existing 8k recipe and adds
the accepted opt-in serial16k source patch chain, parallel pre-audio runtime and
reference integration changes for the original single-device 8k/16k mode manager.
It is not a dual-device migration. No production installation is performed.

Accepted deployed 16k driver reference SHA-256:
`c3e9638d45da696096240a8c455b64a0d3c747a4bcfc41fbb22d75453c2b9fdf`.
Accepted 8k reference:
`9899154c0869a7e7a62112c2cace1e3ebdf2d22a245371559fab15e912de320f`.
These identify prior acceptance artifacts; they are **not** claims of a new
hardware test or byte-identical public binary rebuild. No module is included.

## What is included

- `build/serial16k`: reconstruct the accepted 8k source, opt-in serial16k,
  timeout lifetime/deadline fix and phase-aware CLCC polling. Pending outgoing
  calls use 500 ms wait slices; idle/non-target behavior retains 1000 ms.
  Slice expiry must not become a false command timeout.
- `helpers/preaudio`: submit preparation before Dial, wait for readiness at
  answer, cancel on hangup; per-call ownership, tombstones and PID birth checks
  fence stale cancellation. Unknown cleanup quarantines rather than stealing a
  lock. No host periodic ADB heartbeat after the worker completes, and no 150 s
  call-duration deadline. **Device-local supervision still loops**; launch,
  readiness and RPC timeouts remain. This is not a claim of zero polling.
- `config/dualmode-outbound.patch`: reference dialplan changes, using dynamic
  `${UNIQUEID}` rather than a captured transaction. Adapt to your own dialplan;
  its original context/line numbers are not a patch for the public config tree.
- `build/dualmode`: reference image/upgrade implementation and integration diff.
  Preserve the immutable 8k module slot even when the live mode is 16k. ADB is a
  runtime bind, not an image-build executable dependency. Source hashes bind
  the reference files. Do not apply the diff again to the already-updated copies.
- Offline synthetic tests; no production logs, source archives, credentials,
  device identifiers or captured call transactions are added.

## Reproduce sources and offline tests

Requirements: Git, Python 3, patch, a C compiler and a Linux/POSIX test environment.
The pre-audio tests rely on Linux `/proc`; run them in Linux, not native macOS.
Use fresh output directories. Run from this gateway repository:

```sh
git clone https://github.com/AlchemillaHQ/asterisk-chan-quectel.git /tmp/qdc-upstream
python3 build/serial16k/stage.py --upstream /tmp/qdc-upstream --output /tmp/qdc-16k
python3 build/serial16k/verify.py /tmp/qdc-16k/src
python3 tests/driver/run.py /tmp/qdc-16k/accepted8k
python3 /tmp/qdc-16k/tests/regression.py
python3 /tmp/qdc-16k/tests/lifecycle-regression.py
python3 -B tests/preaudio/run.py
python3 -B tests/dualmode/test_adb_build_fix.py
```

The stage pins upstream `e1c027750bdf878bfe552341de457a9245358ce1`,
verifies the intermediate baseline, then verifies 222 final source files.
Generated regression C/executables/results stay in the disposable output.
The default lifecycle mode is **poison**, not ASAN or mprotect evidence.
`LIFECYCLE_MODE=guard` or `asan` selects stronger optional checks on compatible
hosts; no fresh pass for these optional modes is claimed here.

Saved publication checks reused on resumption: source staging/222-file match;
8k regression including both ringbuffer modes, guard pages, 18 CLCC groups and
13 timeout/hangup semantics; baseline/compat/fast 16k regressions; 17 fixed
lifecycle cases in poison mode with negative controls; 17 fake-ADB pre-audio
tests; three image/ADB isolation tests. Resumption additionally reverified the
222-file manifest and reran the three image/ADB tests. These are offline tests,
not end-to-end Docker/Asterisk/modem acceptance or a long-call stability claim.

## Missing deployment prerequisites / safety boundary

`prepare.py.example` and `agi-wrapper.example` contain `__QDC_SERIAL__` and must
be configured privately. They are templates, not a ready installation. The
reference builders/upgrader retain deployment-specific directory contracts and
hash guards; they require the original cutover planner, verifier, dispatcher,
mode profiles and state/journal, accepted local image/module payloads, the
ARM device bridges/guard and the matching Asterisk ABI. Those complete inputs
and a portable end-to-end dual-mode build recipe are **not supplied here**.
The original private integration directory must not be copied wholesale.

In particular, running the image builder/upgrader is NOT an offline test: it can
inspect local Docker/production state and explicit apply modes can change it.
Only the synthetic test entry points above are safe publication checks.
Do not weaken hash/ABI checks to make a different build appear accepted.
No NAS operation, mode switch, deployment, push or hardware retest is part of
this publication. See [the 8k build/ABI limits](driver-20261018.md).

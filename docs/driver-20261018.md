# Accepted single-device driver — 2026-10-18

## Scope and build integration

This records the accepted **single-device** QDC507 source, not a v5/dual-device
migration or an early-audio experiment. The upstream remains
`AlchemillaHQ/asterisk-chan-quectel` at
`e1c027750bdf878bfe552341de457a9245358ce1`.

The existing Docker build runs `qdc507_patch.py`. It now applies
`production-20261018.patch` **after** the historical patch stack, with a required
`git apply --check`. This small reconciliation patch changes 11 source files;
it is not a copy of a private source tree. Do not apply it directly to upstream
or additionally apply the older `docs/registration-fix.diff`.

The fetched public baseline (`e1bfc46`) contained the registration documentation
but did not execute that diff in its build. Its historical script also generated
a different CLCC implementation (monitor-owned polling, tracked/missing-call
reaping and enqueue-time snapshot reset). The final reconciliation intentionally
replaces those details with the accepted source, rather than silently mixing
unvalidated behavior into this publication:

- Keep CREG and CEREG states independently; either registered domain is usable.
  Query CEREG during generic initialization and retain LTE CLI/JSON status.
- Guard enum lookup **before** indexing, including initial registration `-1`
  converted to `UINT_MAX`; preserve fallback for null/empty entries.
- Preserve the accepted hangup reconciliation: only locally hangup-pending,
  non-INIT calls absent from a valid completed CLCC response are released.
  This is not the alternative tracked-call missing-snapshot reaper.
- Keep serializer-based idle CLCC polling and the 1000 ms outstanding-command
  wait slice. A slice expiry is not a real command timeout; the original deadline
  is re-read and retained. Non-QDC behavior remains unchanged.
- Correct the cross-boundary ringbuffer pattern suffix from `mem + i` to
  `mem + len - i`.

The patch retains the accepted response-handler snapshot reset semantics. This
publication is source alignment, not a claim that all possible multi-call,
partial-response or delayed-modem cases have been resolved.

## Reproduce source and run offline tests

Use a **fresh disposable checkout**: the patch script is intentionally not
idempotent. Python 3, Git and a C compiler are sufficient for the default tests.
From this gateway repository's root:

```sh
git clone https://github.com/AlchemillaHQ/asterisk-chan-quectel.git /tmp/qdc507-source
git -C /tmp/qdc507-source checkout --detach e1c027750bdf878bfe552341de457a9245358ce1
QDC507_SOURCE_ROOT=/tmp/qdc507-source python3 build/clccsafe4/qdc507_patch.py
python3 tests/driver/run.py /tmp/qdc507-source
# On a toolchain with ASAN and UBSAN runtimes installed:
python3 tests/driver/run.py /tmp/qdc507-source --sanitizers
```

The runner verifies all 54 files under upstream `src/` against accepted-source
SHA-256 values before extracting or compiling production functions. Its fixtures
are synthetic; no modem, production config, phone numbers, SMS records or network
access are used. Temporary executables and generated harnesses are removed.
The single-byte reference model explicitly uses target `char` signedness, matching
the existing production API rather than changing that API for a test.

Publication-time checks on Alpine/aarch64 passed:

- Full public patch pipeline; all **222** regular source files matched the
  accepted source tree byte-for-byte (including files outside `src/`).
- Both optimized ringbuffer modes (fallback and libc memmem): each performed
  **1,240,118** search comparisons, **7,040** parser integrations and seven long
  synthetic CMGR boundary cases. The old one-line bug failed the negative control
  as expected.
- **896** guard-page cases.
- CLCC before/after: **18 groups each**, including simulated 6000 → 2000 ms
  stale-wait behavior, real 5000 ms deadline preservation and real pipe reads.
- **13** timeout/hangup semantic checks and six enum boundary assertions.

The optional sanitizer run was attempted here but could not link because this
local toolchain lacks `libasan_preinit.o`, libasan and libubsan. This is not a
sanitizer pass. Previously supplied isolated x86-64 build evidence reports both
ASAN+UBSAN ringbuffer modes passed; leak detection was disabled in that environment.
No fresh hardware access or full Docker/module build was performed for publication.

## Module build and reproducibility boundary

The existing build context is preserved:

```sh
docker build --platform linux/amd64 \
  -f build/clccsafe4/Dockerfile.qdc507 \
  -t qdc507:single-device-20261018 build/clccsafe4
```

This reproduces the **source patch pipeline**, not necessarily the accepted module
bytes or its Asterisk ABI. Debian trixie packages and the Docker builder base are
not fully locked, and its generated Asterisk headers/menuselect can differ from
the deployed environment. Check the target Asterisk build options and dependencies
before loading any rebuilt module. Do not bypass Asterisk's module ABI check.

Accepted deployed module SHA-256:

`9899154c0869a7e7a62112c2cace1e3ebdf2d22a245371559fab15e912de320f`

Supplied isolated build evidence: Asterisk **22.10.1**, ELF64 **x86-64**, GCC
14.2.0-19, CMake 3.31.6, Debian trixie 13.7;
`AST_BUILDOPT_SUM=da6642af068ee5e6490c5b1d2cc1d238`;
`SOURCE_DATE_EPOCH=1792299960`; `MENUSELECT_CFLAGS=OPTIONAL_API`; BUILD_NATIVE off.
The baseline and ringfix rebuild used identical generated headers, CMake options
`-DAST_HEADER_DIR=/usr/src/asterisk/include -DASTERISK_VERSION_NUM=221001`, and no
extra CMAKE_BUILD_TYPE/CMAKE_C_FLAGS. Only the ringbuffer object changed among
24 objects. The three compared artifacts had matching static ABI requirements,
including GLIBC 2.38; that is not a loading or runtime guarantee.

The old production waitslice artifact and the rebuilt waitslice baseline were
**not byte-identical**: deterministic metadata changed package revision
`0506-unversioned` to `0506`, affecting the CLI object, version strings,
relocations and linked sections. Do not interpret the baseline comparison as
bit-for-bit production reproduction. Full private production configuration is
neither required for these source tests nor published.

No `.so` is added: the repository's existing runtime binaries are device/host
recovery tools, while chan_quectel is built from source. No release or tag is
created by this publication. Upstream copyright notices remain in the fetched
source; `build/clccsafe4/COPYRIGHT.txt` and `LICENSE.md` preserve its attribution
and GPL v2 license text. The new driver patch/test material is GPL-2.0-or-later.

## Acceptance evidence and limits

The user reported a call lasting over 30 seconds and receipt of an SMS during a
carrier-service call without disconnecting. Observed CLCC intervals improved
from approximately six seconds to approximately two seconds. These are **short
acceptance observations**, not proof of long-term stability, a complete root-cause
analysis or a promise to eliminate all latency/disconnections. Offline seams do
not replace modem/ALSA/Asterisk integration or extended hardware testing.
